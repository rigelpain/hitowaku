## 決まったこと（会話で合意済み）

ゲームの中身は `docs/GAME.md` を参照。要点だけ：

- 狭い部屋の会話劇はやめ、一行が旅をする形にする。人・選ぶ人・決め方を増やせる器にする
- 犠牲は命ではなく「一行と別れる」
- 基本はターン制、出来事によってだけ制限時間。1回の旅はおよそ10分。旅に seed をつける
- 基本は「高校生1人＋ほかは全部 AI」。全員高校生、全員 AI も可
- 生徒は最初、AI だけの旅を見守り（チュートリアル）、そこから決め方を選ぶ先導者になる
- 人を見る観点はプレイヤーが決める。AI が生活史を読んで数値を割り振る。ほかのプレイヤーの観点を借りられる
- 決め方は歴史上のものを含めて多数用意し、旅の途中で変えたり、決まりを足したりできる
- 感情の演出は選ぶ側にも見せる
- 出来事の設計は、当面は開発側と AI が担う

## 絵の決めごと

- 土台は Return of the Obra Dinn 風の点描を、色つきにしたもの。限られた色の組で、近い2色をベイヤー配列で混ぜる
- 高校生に届くよう、少しずつ寄せていく（明るさ、服やシルエットの見分けやすさ、文字演出）。一度に変えず、版ごとに見比べる
- 人は七頭身くらいのふつうの体型。頭を大きくしない。こけし型にしない。大きく見せる必要もない
- 顔の部品（眼・口など）はつけない（ユーザー確認済み）
- 地形や物は「色の箱」にしない。素材ごとのシェーダーで質感を出す。点描は明るさの差を拾うので、模様は明暗の揺らぎとして入れる
- 人には細い輪郭線（裏面を少し太らせた墨）
- 文字はしっぽり明朝。吹き出しは紙の地に墨の影

### 避けるもの（AI が作りがちな見た目）

参考にした skill：Anthropic の `frontend-design`、Leonxlnx/taste-skill、pbakaus/impeccable、MrBongoC/ai-iso-skill、emilkowalski/skills の `prototype`。

- クリーム地＋テラコッタ、黒地＋蛍光一色、細罫線の新聞風、同じ角丸カードの羅列
- 見出しの上の小さな英大文字ラベル、等幅フォントの飾りラベル、ボタン末尾の「→」、見出しの一語だけ色を変える
- 紫〜青のグラデーション、ガラス風のぼかし、絵文字アイコン
- すべての要素がふわっと出てくる動き。動きは一か所に絞る。入りは ease-out、UI の動きは 300ms 以内、`prefers-reduced-motion` を守る

## 感情の演出（いまの実装と、これから）

| 感情 | 人の像 | 吹き出し・文字 | 画面・天気 |
| --- | --- | --- | --- |
| 張りつめ | 震える、肩が上がり腕が縮こまる | 字が一字ずつ震える、言いよどむ | 点描の閾値が這う、行が横にずれる、コントラスト上昇 |
| 悲しみ | 服の色が抜ける、うつむく | 字がにじみ、下へ沈み、間が開く | 色が抜ける、粒が粗くなる、雨 |
| 希望・あたたかさ | （未実装）まわりに光の粒 | （未実装）字がはっきり、温かい色 | 話し手のまわりが明るむ |
| 言いよどみ・隠し事 | （未実装）像の一部が点描に埋もれる | （未実装）一部の語が伏せ字 | 変化なし |

参考：ユーザーが共有した「Wishing pond」の動画。入力した言葉で池の天気が変わり、UI のカード自体も水に揺れる。UI を画面の上に置かず、世界の一部として揺らすのが狙い。

候補者の AI には、発言と別に感情の種類と強さを JSON で返させ、その値で演出を動かす想定。

## 安全（最初から入れる）

- 演出の強さを授業者が決められる（0〜3段階）。生徒もいつでも止められる
- 光の点滅は1秒に3回以下、画面の大部分を一気に光らせない。`prefers-reduced-motion` では揺れを止め、色の変化だけにする
- 実在の生活史では強い演出を既定で切る。実在の生活史は本人の同意が前提
- 旅のあとに「演出なしで同じ会話を読み直す」画面を出し、印象の変化を書き留めて降りてくる
- API キーは BYOK。既定は sessionStorage、書き出しに含めない（`main` の `js/store.js` を参照）

## わかっている課題

1. **色の組が一つしかないので、素材どうしが色を取り合う**。肌の影が緑に寄る、日なたの板が朱に化ける、など。次にやるべき技術課題は「素材ごとの色の組」。描画時に素材 ID を別のバッファに書き、点描のときに ID ごとの色の組から選ぶ（Obra Dinn と同じ考え方）
2. 悲しみの場面で、草まで灰色に寄りすぎる（画面全体の脱色が強い）。人と世界で効き方を分けたい
3. 舟に乗り込む動きが瞬間移動。乗り込む・手を振る・振り返る、の動きがない
4. 文字演出の揺れは DOM を毎フレーム書き換えている。人数が増えたら canvas か WebGL の文字に移す
5. 雨がまだ目立たない
6. 録画用の環境（GPU なし）では1分の動画に8分かかった。手元の GPU なら実時間で見られる

## 次の一歩（提案）

1. 素材ごとの色の組（課題1）
2. 高校生に届く寄せ方を一段だけ試す。服・髪型・持ち物でシルエットを見分けやすく、色を少し明るく。版を並べて見比べる
3. 台本で動いている部分を、出来事・決め方・投票のデータ構造に置き換える（`docs/GAME.md` の決め方一覧を JSON に）
4. AI（BYOK）で、出来事に対する案と感情の強さを実際に生成させる
5. 観点の仕組み：プレイヤーが観点を決め、AI が生活史から数値と根拠を割り振る
